# traceroute — полный аналог Linux `traceroute` для Windows (C#)

Точная реплика программы `traceroute` из пакета Linux (Dmitry Butskoy, «Modern
traceroute»), реализованная на C#/.NET для Windows.

**Вывод совпадает с оригиналом байт-в-байт**: заголовок, нумерация хопов,
формат `%.3f ms`, звёздочки ` * ` для таймаутов, обратный DNS (`имя (ip)`) и
коды ошибок ICMP (`!H`, `!N`, `!X`, `!P`, `!F-N`, `!S`, `!V`, `!C`).

## Сборка и запуск

```powershell
dotnet build -c Release
.\bin\Release\net8.0\traceroute.exe 8.8.8.8
```

Работает из-под обычного пользователя (без прав администратора) — Windows
разрешает создание ICMP raw-сокета обычным пользователям.

Один автономный exe:

```powershell
dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

## Пример вывода

```
traceroute to 8.8.8.8 (8.8.8.8), 30 hops max, 60 byte packets

12  8.8.8.8 (dns.google)  21.491 ms  21.370 ms  21.302 ms
```

## Использование и ключи

```
Usage: traceroute [-46dFITnreAUDV] [-f first_ttl] [-m max_ttl] [-p port] [-N squeries]
                  [-q nqueries] [-s src_addr] [-t tos] [-i device] [-g gateway]
                  [-M name] [-P protos] [-l len] [-z sendwait] [-UL] [-D]
                  [-O option] [--version] [--help] [hostname [packetlen]]
```

Полный список ключей тот же, что и у оригинала. Поддерживаются:

| Ключ | Назначение | Статус на Windows |
|------|------------|-------------------|
| `-4` / `-6` | IPv4 / IPv6 | `-4` работает; `-6` не поддерживается |
| `-f first_ttl` | начальный хоп | ✅ |
| `-m max_ttl` | макс. число хопов (по умолчанию 30) | ✅ |
| `-q nqueries` | проб на хоп (по умолчанию 3) | ✅ |
| `-N squeries` | параллельных проб | ✅ (см. примечание) |
| `-p port` | базовый порт / нач. последовательность | ✅ |
| `-n` | не делать обратный DNS | ✅ |
| `-s src_addr` | исходный адрес | ✅ |
| `-t tos` | TOS | ✅ |
| `-w MAX,HERE,NEAR` | таймаут ожидания | ✅ |
| `-z sendwait` | интервал между пробами | ✅ |
| `-F` | не фрагментировать | ✅ |
| `-r` | миновать таблицу маршрутизации | ✅ |
| `-d` | отладка сокетов | ✅ |
| `-I` / `--icmp` | метод ICMP ECHO | ✅ (используется по умолчанию) |
| `-T` / `--tcp` | метод TCP SYN (порт по умолчанию 80) | ✅ (требует прав администратора) |
| `-U` / `--udp` | метод UDP | ⚠️ см. ниже |
| `--help`, `--version` | справка / версия | ✅ |
| `hostname [packetlen]` | цель и длина пакета | ✅ |

Ключи, которые принципиально не реализуемы в Windows (`-6`, `-D`, `-UL`,
`-P`, `-g`, `-i`, `-e`, `-A`, `-l`, `-O`, `--sport`, `--fwmark`, `--mtu`,
`--back`) принимаются и, как в оригинале при ошибочном ключе, завершают работу
с кодом 2, сообщая причину.

## Метод TCP (`-T`)

Реализован, как в оригинале: формируется корректный SYN-пакет (IPv4+TCP
заголовки с проверочными суммами) с нарастающим TTL и отправляется через raw-
сокет `IPPROTO_RAW` (`IP_HDRINCL`).

Windows накладывает два ограничения, которые нужно учитывать:

* **Требуются права администратора** — raw-TCP/`IPPROTO_RAW` сокеты доступны
  только администраторам. Без администрирования `-T` выводит понятное
  сообщение и код выхода 2.
* **Windows не доставляет ICMP-ответы «time exceeded»** для пакетов,
  отправленных не из raw-ICMP-сокета (та же проблема, что и с UDP). Поэтому
  промежуточные маршрутизаторы чаще всего будут отображаться как `*`.
  Ответ цели (TCP SYN-ACK / RST) принимается отдельным raw-TCP-сокетом.

Пакет корректно формируется (проверено: верные IP- и TCP-контрольные суммы,
правильные длина и TTL). На большинстве сборок Windows полную трассу по маршруту
можно получить только методом по умолчанию (ICMP) — он и рекомендуется.

## Важное о методе проб

Оригинальный `traceroute` по умолчанию шлёт **UDP**-дейтаграммы и читает ответы
ICMP «time exceeded» / «port unreachable».

Ограничение Windows: **ICMP-ответы, порождённые UDP-потоком, не доставляются
Windows в raw-сокет** (в отличие от Linux). Проверено: UDP-пробы с TTL=1 даже к
собственному шлюзу и к loopback не дают ни одного ответа в raw-сокете, тогда как
ICMP ECHO работает без проблем.

Поэтому метод пробы в этой реализации — всегда **ICMP ECHO** (это единственный
рабочий способ на Windows). Вывод при этом абсолютно идентичен выводу
оригинала. Если запрошен UDP-метод (`-U`), выводится уведомление в stderr и
трассировка выполняется тем же ICMP-методом.

`-p` в этом случае задаёт начальную последовательность проб (как для `-I` в
оригинале). `-N` ограничивает число одновременно отправляемых проб (максимум
одного хопа за раз).

## Как это устроено

- ICMP-пробы (`type 8`) отправляются raw-сокетом с протоколом ICMP; TTL
  наращивается от хопа к хопу и выставляется через `socket.Ttl`.
- Ответы (`ECHO REPLY`, `TIME EXCEEDED`, `DEST UNREACHABLE`) читаются тем же
  raw-сокетом. Windows возвращает заголовок IP + ICMP.
- Проба сопоставляется по полю `identifier` (PID процесса) и `sequence`.
- Формат строки хопа воспроизводит оригинальную функцию `print_probe()`:
  `\n%2u ` для номера, ` %s (%s)` для адреса, `  %.3f ms` на ответ, ` *` на
  таймаут, и суффиксы ошибок ICMP.
- Обратный DNS выполняется через `Dns.GetHostEntry` (отключается ключом `-n`).

## Быстродействие (как у Linux)

Как и оригинал, утилита использует **конвейерный режим `-N`** (по умолчанию 16
одновременных проб через несколько хопов) и **адаптивный таймаут** `-w`
(MAX=5 c, HERE=3×RTT, NEAR=10×RTT). Это даёт такую же скорость, как у Linux:

* полностью отвечающие маршруты — практически мгновенно (доли секунды);
* при недоступных маршрутизаторах трасса **останавливается сразу же, как
  только достигнута цель** (`NEAR`-фактор мгновенно сворачивает ожидание уже
  «мёртвых» хопов), не дожидаясь таймаута по каждому из них;
* реальную цену платит только «первая волна» неотвечающих роутеров, идущих
  перед целью (не более MAX=5 c) — то же самое, что и в Linux с настройками
  по умолчанию.

На проверенном маршруте до `ya.ru` (6 неотвечающих хопов подряд перед целью)
время упало с ~30 c до ~5 c, а до `8.8.8.8` — с ~10 c до ~0,2 c.

## Установка через MSI

В каталоге `Projects` лежит готовый установщик **`traceroute.msi`** (Windows
Installer, x64) и исходники для его сборки (`installer.wxs`, `build_msi.ps1`).

MSI-установщик:
* устанавливает `traceroute.exe` в **`C:\Windows\System32`** (настоящий 64-битный
  системный каталог), поэтому команда доступна из любой консоли как `traceroute`;
* регистрирует программу в «Установка и удаление программ» и полностью
  поддерживает деинсталляцию;
* является пакетом **per-machine** (требует прав администратора — UAC);
* имеет фиксированный `ProductCode` и `MajorUpgrade` — новая версия корректно
  заменяет предыдущую.

Установка (двойной клик или командная строка администратора):

```
msiexec /i traceroute.msi
```

Деинсталляция:

```
msiexec /x traceroute.msi
```

или через «Установка и удаление программ» → Traceroute.

### Пересборка MSI после изменения кода

```
pwsh -File build_msi.ps1
```

Скрипт сам публикует утилиту в один автономный exe (`publish\traceroute.exe`),
устанавливает WiX Toolset как dotnet-инструмент (если его нет) и собирает
`traceroute.msi`.
